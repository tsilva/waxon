# TypeSafe AI Jev: source check

## Identification

"Typesafe AI JEV" most likely means **Jev**, TypeSafe AI's first public System One model. TypeSafe announced it on September 15, 2026 and described it as available in early access. I found no separate TypeSafe product called "JEV"; the capitalization appears to be a spelling variant. ([TypeSafe launch announcement](https://typesafe.ai/blog/introducing-system-one-models-and-jev), [model documentation](https://docs.typesafe.ai/models.md))

## Verified capabilities

- The service evaluates a text or structured JSON `state` against named questions through `POST /v1/systemone`. Questions in one request see the same state and are evaluated independently. ([API reference](https://docs.typesafe.ai/api.md), [state guide](https://docs.typesafe.ai/concepts/state.md))
- A `Noul` returns a yes probability; a `Choice` selects one of up to 255 named options and returns their probability distribution; a `Score` evaluates an ordered rubric of two to ten levels and returns a probability-weighted score. Choice and Score also return `confidence`, which summarizes how concentrated their distributions are. Noul has no separate confidence field. ([API reference](https://docs.typesafe.ai/api.md), [confidence guide](https://docs.typesafe.ai/confidence.md))
- Jev does not generate prose or explanations. TypeSafe recommends focused judgments that a knowledgeable person can make quickly, then combining those judgments in code. ([primitives guide](https://docs.typesafe.ai/primitives.md), [known limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md))
- TypeSafe publishes a JavaScript and TypeScript SDK, `@typesafe-ai/sdk`, requiring Node.js 20 or newer. It infers answer types from question definitions. ([official SDK guide](https://docs.typesafe.ai/sdk/javascript.md), [official repository](https://github.com/typesafe-ai/typesafe-sdk-js))

## Maturity and operational limits, as published September 23, 2026

- Jev remains an early access service. The current versioned model is `jev-1.13.0`; `jev-latest` is a moving alias. TypeSafe recommends pinning a version if decision thresholds were tuned against it. ([launch announcement](https://typesafe.ai/blog/introducing-system-one-models-and-jev), [models](https://docs.typesafe.ai/models.md))
- The published price is $0.042 per million input tokens with free output tokens. The listed limits are 250,000 input tokens per second, 1,200 requests per minute, 64,000 total tokens per request, and 32,000 tokens for the state plus the longest question. TypeSafe warns that rate limits can change without notice. These are vendor claims, not measurements made for Waxon. ([models](https://docs.typesafe.ai/models.md))
- Input is text only. English is its strongest language. TypeSafe documents weaker performance on other languages, long irrelevant context, numeric precision, date comparison, multi-step reasoning, and adversarial text. It specifically says to keep arithmetic in code. ([models](https://docs.typesafe.ai/models.md), [known limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md))
- Typed output constrains *format*, not factual correctness. The published `confidence` for Choice and Score is derived from the option distribution; it is not an independent probability that a judgment is correct. TypeSafe advises testing thresholds on each application's own data. ([API reference](https://docs.typesafe.ai/api.md), [confidence guide](https://docs.typesafe.ai/confidence.md), [known limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md))
- TypeSafe says it does not train Jev on customer requests or responses. Zero data retention is offered to enterprise customers; the standard retention terms require separate review before sending private learner content. ([models](https://docs.typesafe.ai/models.md), [legal overview](https://docs.typesafe.ai/legal.md))

## Product-relevant boundary

Jev's stated strengths suggest testing it on narrow, independently checkable classifications. The product specification requires substantive answer checking, explanatory feedback, and correction support. Jev cannot generate that feedback. The spec also bars a model's self-reported confidence from affecting Recall Result, retries, Answer Grade, or scheduling. Whether a Noul's yes probability counts as confidence for live grading needs stakeholder interpretation; the proposed offline comparison avoids that ambiguity. This is an inference from the model contract and [Waxon's requirements](../../SPECS.md), not a demonstrated Jev evaluation on Waxon data.

## Ranked fits for Waxon

1. **Question quality checks.** The current [validator](../../app/lib/v2/questionQuality.ts) relies on explicit patterns, so a well-formed prompt can pass despite testing two facts, depending on missing context, giving away the answer, or having an answer standard that does not answer the prompt. Jev could judge these separate conditions in one request against the prompt and answer standard. Code should still reject missing or unusable input and preserve the rule that semantically questionable candidates become Flagged with reasons. This is the best first experiment because each judgment maps to the [Question Quality Standard](../../reference/question-quality.md). Jev's own guidance favors narrow questions over one broad quality score. ([primitives guide](https://docs.typesafe.ai/primitives.md), [known limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md))
2. **Similar-question triage.** Waxon's [question search](../../app/lib/v2/questionSearch.ts) already retrieves candidates with lexical and embedding signals. Jev could compare only the short list of candidate pairs and label each as the same recall target, related but different, or different. That may reduce false alarms from topical similarity. It must remain advice to the learner or MCP client; the [product spec](../../SPECS.md) forbids semantic similarity from automatically merging questions. TypeSafe documents both short-list re-ranking and pairwise entity alignment, but neither demonstrates accuracy for Waxon questions. ([re-ranking cookbook](https://docs.typesafe.ai/cookbooks/rerank_typesafe.md), [entity alignment cookbook](https://docs.typesafe.ai/cookbooks/entity_alignment.md))
3. **Answer-grading comparison, offline first.** Run Jev's Incorrect/Partial/Correct Choice on the prompt, answer standard, and learner answer, then compare it with corrected answer histories and the current [evaluator](../../app/lib/v2/model.ts). This tests whether its fast decision is useful. It cannot replace the live evaluator by itself: Waxon requires feedback naming the expected answer and gap, while Jev does not generate text. Its separate confidence field cannot control the recall result, retries, grade, or schedule under the [product spec](../../SPECS.md). Jev's documented trouble with math and multi-step reasoning makes coverage across subjects essential. ([System One documentation](https://docs.typesafe.ai/concepts/system-one.md), [known limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md))

Do not use Jev to change Review scheduling, create questions from source material, or persist per-question Tag labels. The [product spec](../../SPECS.md) assigns scheduling to answer-grade history, excludes source ingestion and automatic source question generation, and requires read-time Tag relevance from compatible embeddings and prompt matches. A Jev Tag-ranking experiment would first need a stakeholder change to that Tag requirement. These are scope conclusions, not empirical claims about Jev.

## First pilot

Use a private, labeled set of Waxon question candidates that includes clear passes, each quality failure, tricky near duplicates, and multilingual or technical examples. Compare Jev's quality flags with the current validator and human labels, counting false Active decisions separately from false Flagged decisions. Pin the model version, record latency and token cost, and keep the pilot read-only. This recommendation follows TypeSafe's advice to calibrate decisions on the application's own data and its warning that model aliases move. ([confidence guide](https://docs.typesafe.ai/confidence.md), [models](https://docs.typesafe.ai/models.md))
